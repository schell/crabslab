## 5.1 WGSL validation

All `#[wgsl]` modules with no imports validate at compile time via naga.
Modules with imports validate at test time via auto-generated
`__validate_wgsl()` tests.

**Current status:** Blocked. The generated WGSL does not validate with naga
because companion types (`DataId`, `DataArray`, etc.) generated by
`#[slab_module]` are missing from the WGSL output. See "Attribute ordering
issue" below.

### Attribute ordering issue

Proc-macro attributes in Rust are applied **top-to-bottom** (outermost first).
With the original ordering:

```rust
#[wgsl_rs::wgsl(skip_validation)]   // runs FIRST — doesn't see companion types
#[crabslab::slab_module]            // runs SECOND — generates companion types
pub mod apply_data_changes { ... }
```

`#[wgsl]` processes the module before `#[slab_module]` has generated the
companion types (`DataId`, `DataArray`, etc.), so the WGSL output references
undefined types and functions (`DataArray_at`, `AnyChangeId_from_array`, etc.).

**Fix:** Swap the attribute order so `#[slab_module]` is outer (runs first):

```rust
#[crabslab::slab_module]            // runs FIRST — generates companion types
#[wgsl_rs::wgsl(skip_validation)]   // runs SECOND — sees all types
pub mod apply_data_changes { ... }
```

**Blocker:** With the corrected attribute order, the `#[wgsl]` parser rejects
`[0u32; N]` repeat expressions generated by `#[slab_module]`'s `to_array` and
nested `from_array` functions. wgsl-rs does not currently support
`syn::Expr::Repeat`. This needs to be fixed in wgsl-rs before WGSL validation
can be enabled.

Once wgsl-rs supports `[0u32; N]`:
1. Swap the attribute order in `test.rs`
2. Remove `skip_validation`
3. Verify naga validates the complete WGSL (including companion type definitions)

### Other wgsl-rs compatibility notes for companion types

The companion types use these patterns which wgsl-rs needs to handle:

- `[0u32; N]` repeat expressions (in `to_array` functions)
- `[u32; Type::SLAB_SIZE]` array type annotations (path expr in const position)
- `Type::SLAB_SIZE` path expressions in arithmetic (offsets, sizes)
- `slab_read_array!` / `slab_write_array!` macros (already supported)
- Struct literals `Type { field: value }` (already supported)
- `#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]` on structs (silently
  stripped by `#[wgsl]`, no issue)
- `impl crabslab::SlabItem for X` trait impls (classified as `TraitImpl` by
  `#[wgsl]`, silently skipped, no issue)

## 5.3 GPU-side tests

Run the wgpu-based tests with the new WGSL shader. Compare results with the CPU
backend to verify correctness.

**Status:** Not started. The `linkage-wgpu` module is available and generates
the shader module, bind group layout, and compute pipeline. GPU tests can use
`skip_validation` (the shader still runs correctly on the GPU; only naga's
compile-time check is skipped).

### Implementation plan

Add a `TestBackendWgpu` struct that holds the wgpu pipeline and atomic counter
buffers. Implement `BackendUpdate for GpuUpdateTest<WgpuRuntime, TestBackendWgpu>`.

**`TestBackendWgpu` fields:**
- `bind_group_layout: wgpu::BindGroupLayout`
- `pipeline: wgpu::ComputePipeline`
- `invocations_ran_buffer: wgpu::Buffer`
- `invocations_skipped_buffer: wgpu::Buffer`

**Constructor** uses `apply_data_changes::linkage::*`:
- `linkage::shader_module(device)`
- `linkage::bind_group_0::layout(device)`
- `linkage::main::pipeline_layout(device, &[&bg_layout])`
- `linkage::main::compute_pipeline(device, Some(&pl), &module)`
- Create two 4-byte `STORAGE | COPY_SRC | COPY_DST` buffers for atomic counters

**`apply_backend_changes` method:**
1. Zero counter buffers via `queue.write_buffer`
2. Get data slab and changes slab buffers from their arenas
3. Create bind group via `linkage::bind_group_0::create`
4. Encode compute pass: set pipeline, set bind group, dispatch workgroups
5. Copy counter buffers to staging buffers, submit, poll
6. Map staging buffers, read back `u32` values
7. Return `(ran, skipped)`

**Three GPU tests:**
- `gpu_update_test_sanity_on_gpu`
- `gpu_array_update_test_sanity_on_gpu`
- `proptest_gpu_updates_checked_on_gpu` (smaller bounds for speed)
